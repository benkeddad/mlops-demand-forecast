# Prefect 2.14.x's own code does `from griffe.dataclasses import Docstring`
# (prefect/utilities/callables.py) - griffe 1.x removed that module entirely
# (reorganized into the griffe top-level package), which crashes `import
# prefect` with ModuleNotFoundError. Prefect's own setup only declares
# griffe>=0.20.0 (no upper bound), so pip happily picks the newest 1.x
# unless capped here. Pinned to an exact 0.x release (rather than left as
# `<1.0.0`) because griffe 0.48+ added a deprecation shim to that same
# `griffe.dataclasses` module ahead of the 1.0 removal - harmless, but it
# fires a DeprecationWarning on every `import prefect` (i.e. on every test
# run and app boot). 0.47.0 is the newest release before that shim landed,
# still well inside Prefect's own declared floor.
griffe==0.47.0

# psycopg2-binary's 2.9.0 release (the original pin here) never published a
# cp312 wheel - its last binary wheels stop at cp39. api.Dockerfile builds on
# python:3.9-slim so that pin never broke the container build, but running
# `pip install -r requirements.txt` directly on any machine with Python 3.10+
# (which includes a stock Ubuntu 24.04 install - it ships 3.12 by default and
# doesn't carry python3.9 in its standard repos) fails immediately: pip falls
# back to building psycopg2 from source and dies on a missing `pg_config`
# unless libpq-dev happens to be installed. 2.9.10 publishes wheels through
# current Python versions and is a drop-in replacement.
